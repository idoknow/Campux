# 登录与密码接口

本文覆盖普通用户进入校园墙的三条路径与两类密码操作：QQ 号自助注册、QQ 聚合登录（OAuth）、忘记密码，以及登录后的修改密码。运营管理员的开墙注册见[账号与权限](/admin/accounts)。

## 游客注册

开启「管理 · 插件配置 · 游客投稿」后，校园墙登录页出现注册入口。

注册需要填 **QQ 号、用户名、密码**。是否还要邮箱验证码由管理员在「管理 · 墙面设置 · 注册与邮箱验证」决定：

- **关闭邮箱验证**：只填 QQ 号 + 用户名 + 密码即可注册；
- **开启邮箱验证**：还要填邮箱并收验证码，且邮箱后缀必须在管理员配置的允许列表内。
  列表为空表示**不限制后缀**，任意合法邮箱都可以。

特殊规则：如果你填的是 `<QQ号>@qq.com` 形式的 QQ 邮箱，登记的 QQ 号必须与邮箱前缀一致
（例如邮箱 `123456@qq.com` 就只能用 QQ 号 `123456` 注册），避免用别人的 QQ 邮箱注册。
`foxmail.com` 不在此列——它虽然属于腾讯，但前缀不保证是 QQ 号。

| 接口 | 说明 |
| --- | --- |
| `GET /api/auth/tenant-registration` | 读取是否开放注册、是否需要邮箱验证、允许的后缀 |
| `POST /api/auth/tenant-register/request-code` | 发送注册验证码（仅开启验证时可用） |
| `POST /api/auth/tenant-register` | 注册。开启验证时需带 `email` 与 `code` |

- 注册成功直接建立会话，并成为该墙的「用户」（`submitter`）。
- `400`：邮箱后缀不允许、QQ 邮箱与 QQ 号不一致、验证码错误或过期
- `403`：该墙未开启游客注册
- `409`：QQ 号或邮箱已被注册
- `502`：验证码发送失败（发件服务不可用）

### 登录方式

注册后可以用 **QQ 号 + 密码** 或 **邮箱 + 密码** 登录，两者等价。

## 发件服务

注册验证码、密码重置、账号绑定验证码都通过管理员配置的发件服务发送：

| 模式 | 说明 |
| --- | --- |
| 官方发件 | 使用平台自带的 Resend（`RESEND_API_KEY` / `RESEND_FROM_EMAIL`），与运营管理员注册同一套。官方托管服务默认用它 |
| 自定义 SMTP | 运营者自备 SMTP（QQ/163 授权码、自建 Postfix）。自托管部署通常用这个 |

两条硬性规则：

1. 开启邮箱验证前，发件配置必须完整可用，否则保存会被拒绝（`MAIL_SENDER_INCOMPLETE`）；
2. 修改发件配置后，必须先发送一封测试邮件并确认收到，才能保存（`MAIL_SENDER_UNVERIFIED`）。
   测试通过后验证凭据只对**当时的配置**有效——任何字段再改动都要重新测试。

## 账号合并

管理员切换运营模式后，**还没绑定邮箱**的账号在下次登录时会被询问
「是否绑定之前的账号」——把无 Bot 期用网页注册的旧号并进当前账号。

- 输入旧账号 QQ 号 → 查询预览（会显示可迁移的稿件数）；
- 验证码发到**旧账号绑定的邮箱**；
- 邮箱绑定的 QQ 与当前登录账号不一致时会明确提示；确认后两个账号的稿件与身份合并，
  旧账号停用但仍保留记录供审计。
- 已绑邮箱或已合并过的账号不会再被询问。
- 跳过也没关系：「服务 · 账户设置 · 绑定之前的账号」可以随时补做。

### 合并后用旧凭据登录

合并**不影响登录方式**：旧账号的 QQ 号、邮箱、密码都仍然可用，登录时会自动解析到合并后的主账号。

| 登录方式 | 结果 |
| --- | --- |
| 旧 QQ 号 + 密码 | 登录到主账号 |
| 旧邮箱 + 密码 | 登录到主账号 |
| 主账号 QQ 号 + 密码 | 登录到主账号 |
| 主账号邮箱 + 密码 | 登录到主账号 |

用旧凭据登录时，响应里会带 `mergedAccount`（含 `mergedFromQqUin`），前端提示
「该账号已合并，已为你登录到合并后的账号」。忘记密码同样作用于主账号——
用旧邮箱收到的验证码重置的是主账号密码，不会出现「改了密码却登不进」的情况。

| 接口 | 说明 |
| --- | --- |
| `GET /api/me/account-merge` | 查询是否需要提示 |
| `POST /api/me/account-merge/preview` | 按旧 QQ 号查询可合并的账号与稿件数 |
| `POST /api/me/account-merge/request-code` | 发送验证码到旧账号邮箱 |
| `POST /api/me/account-merge/confirm` | 校验验证码并执行合并 |

审计记录：`user.merge`。


`POST /api/auth/tenant-register`

```json
{ "qqUin": "123456789", "displayName": "路人甲", "password": "至少 6 位" }
```

- 注册成功直接建立会话，并成为该墙的「用户」（`submitter`）。
- `403`：该墙未开启游客注册
- `409`：QQ 号已注册

只读查询入口是否开放：`GET /api/auth/tenant-registration` → `{ "enabled": true, "operateMode": "manual" }`。

## QQ 聚合登录（OAuth）

登录页的第三方按钮由聚合登录插件驱动，QQ 需要同时满足：插件启用、`loginTypes` 勾选 `qq`、并配好 `appId` / `appKey` / `endpoint`。

| 接口 | 说明 |
| --- | --- |
| `GET /api/public/aggregate-login/config` | 登录页读取可用的登录方式（无需登录） |
| `GET /api/auth/aggregate-login/login-url?type=qq&returnTo=/posts` | 换取第三方授权跳转地址，同时种下 HttpOnly 的防 CSRF state cookie |
| `GET /api/auth/aggregate-login/callback?code=...` | 聚合站回跳，完成登录或绑定 |

**自动建号**：插件配置项 `aggregateLogin.autoCreateAccount` 控制首次扫码的行为。

- `false`（默认）：未绑定的第三方身份不建号，回登录页提示先登录已有账号完成绑定。
- `true`：首次扫码自动创建投稿账号并加入本墙。聚合站返回的是 openid、不暴露真实 QQ 号，因此账号用生成的合成 QQ 号，真实身份由 `OAuthIdentity` 关联；初始密码随机，用户可通过忘记密码流程自行设置。

自动建号只在本墙会员关系下生效（创建为该墙的 `submitter`），与游客注册同口径。

## 忘记密码

两步式，未登录可用。账号可以填 QQ 号或邮箱。

### 重置渠道由运营模式决定

不管墙切没切过运营模式，重置密码**只看当前模式**：

| 当前模式 | 重置方式 |
| --- | --- |
| 墙号机器人模式（`bot`） | 私聊墙号发送 `#重置密码`，机器人把新密码私信发给你 |
| 无 Bot 模式（`manual`） | 网页登录页 →「忘记密码」，用邮箱验证码重置 |

机器人模式下网页的忘记密码入口会返回 `409` + `code: USE_BOT_RESET`，并提示去私聊墙号，
不会真的发邮件；无 Bot 模式下私聊 `#重置密码` 也会被拒绝并提示改用网页。

**合并账号始终重置主账号**：不论用旧号还是主账号的凭据发起，也无论是私聊还是网页，
最终改的都是合并后的那个账号的密码；旧号密码不受影响。

**只靠聚合登录（OAuth）建号的同学注意**：这类账号没有 QQ 号可用于私聊，机器人模式下
`#重置密码` 走不通。若该账号也未绑定邮箱，网页忘记密码会返回 `409 RESET_UNAVAILABLE`，
需要联系校园墙管理员重置。建议在「服务 · 账户设置」里绑定邮箱或第三方身份，
以便日后自助找回。

### 验证码投递失败时不会回显

未认证接口只有在**本实例完全没有邮件服务**（既没配 `RESEND_API_KEY` 也没配该墙 SMTP）时
才回显验证码，用于让自托管环境可注册。一旦配置了邮件服务但发送失败，接口返回
`502`，并作废刚生成的验证码——不会把验证码交给未认证的调用者。

### 第一步：发送验证码

`POST /api/auth/password/forgot`

```json
{ "account": "123456789" }
```

**发送频率限制**（按账号维度）：

| 限制 | 值 | 超限响应 |
| --- | --- | --- |
| 两次发送最小间隔 | 60 秒 | `429`，`retryAfterSeconds` 给出剩余秒数 |
| 每小时发送上限 | 5 次 | `429`，`retryAfterSeconds = 3600` |

**验证码有效期** 10 分钟，响应里的 `expiresInSeconds = 600`。

按账号绑定情况走两条通道：

- **已绑定 QQ 邮箱**：验证码发到邮箱，响应 `{ "ok": true, "channel": "email", "email": "ab***@qq.com", "expiresInSeconds": 600 }`。站点未配置邮件服务时额外返回 `devCode`，方便自托管环境使用。
- **未绑定邮箱但绑定过第三方身份**：改走第三方身份验证，响应 `{ "ok": true, "channel": "identity", "providers": ["qq"], "devCode": "...", "expiresInSeconds": 600 }`。
- **既没邮箱也没第三方身份**：`409` + `code: "RESET_UNAVAILABLE"`，提示联系校园墙管理员重置。

| 错误码 | HTTP | 含义 |
| --- | --- | --- |
| `RATE_LIMITED` | `429` | 发送过于频繁或超过每小时上限 |
| `RESET_UNAVAILABLE` | `409` | 账号没有任何可用的验证渠道，需管理员介入 |

### 第二步：校验并重置

`POST /api/auth/password/reset`

```json
{ "account": "123456789", "code": "123456", "newPassword": "新密码至少 6 位" }
```

- 成功：`{ "ok": true }`，同时清空该账号所有会话，旧登录态立即失效。
- 验证码一次性消费，重复使用会被拒绝。

| 错误码 | HTTP | 含义 |
| --- | --- | --- |
| `CODE_MISSING` | `400` | 还没获取过验证码 |
| `CODE_EXPIRED` | `400` | 验证码已过期，需要重新获取 |
| `CODE_ATTEMPTS` | `429` | 单条验证码错误尝试已达 5 次 |
| `CODE_INVALID` | `400` | 验证码不正确，响应会提示剩余尝试次数 |

## 修改密码（已登录）

服务页「账户设置 · 修改密码」。

`POST /api/auth/password`

```json
{ "currentPassword": "旧密码", "newPassword": "新密码至少 6 位" }
```

- `401`：当前密码不正确
- 成功：`{ "ok": true }`

首次通过机器人建号、需强制改密的账号走 `POST /api/auth/password/required`，只提交 `newPassword`。

## 登录页的展示顺序

1. QQ 号 / 邮箱 + 密码登录
2. 第三方登录按钮（聚合登录启用时）
3. 游客注册入口（游客投稿插件启用时）
4. 「忘记密码？」入口

## 安全边界

- 验证码只存哈希（`sha256(邮箱或身份标识 + 验证码)`），库里没有明文验证码。
- 忘记密码的 state 与验证码都按账号隔离，不能跨账号使用。
- 重置成功后强制清空会话，避免旧 token 继续有效。
- 自助重置依赖账号自己的邮箱或第三方身份；两者都没有时必须由校园墙管理员处理。
