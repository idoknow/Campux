# 无 Bot 模式全流程手册

无 Bot 模式（`operate_mode = manual`）指**完全不接入 QQ 机器人**也能运营校园墙。

它的核心变化只有一条：**审核通过的稿件不会自动发到 QQ 空间**，而是停在「待发布」队列，
由管理员在网页端渲染图片、复制文案、手动发出去，再回来确认。

本文按实际操作顺序，把这条链路上的每一步、每个功能、每种边界情况都写清楚。

- 想先了解「为什么这么设计」和两种模式的差异，看 [无 Bot 模式运营](/operator/no-bot-mode)
- 想查接口与错误码，看 [待发布队列接口](/reference/pending-publish)
- 本文面向**运营者**，`admin` / `reviewer` / 用户三种角色都会覆盖

## 一、两种模式的差异

| 能力 | 墙号机器人模式（`bot`） | 无 Bot 模式（`manual`） |
| --- | --- | --- |
| 用户进站 | 私聊墙号自动注册 | 只能靠「游客投稿」 |
| 审核通过 | 自动进发布队列 | 停在「待发布」等你手动发 |
| 发布到 QQ 空间 | 程序自动发 | 你手动发，回来点「确认已发布」 |
| 审核群通知 | 新稿、通过、失败都有通知 | **没有**，要自己盯页面 |
| 撤回说说 | 程序设为仅自己可见 | **删不了**，需手动删除后回来确认 |
| 空间数据（浏览/赞/评论） | 自动同步 | **没有**（无发帖记录，拉不到） |
| 评论管理 / 热度榜 | 可用 | 不可用 |
| 用户忘记密码 | 私聊墙号 `#重置密码` | 网页「忘记密码」+ 邮箱验证码 |
| 发布目标 / cookies | 需要配置 | **不需要**，也不用管 |

::: tip 一句话理解
机器人模式 = 系统帮你发；无 Bot 模式 = 系统帮你**准备**，你来发。
:::

## 二、前置条件：必须有进站通道

这是无 Bot 模式**唯一会卡住开墙**的硬条件。

### 为什么必须有

机器人模式下，普通同学私聊墙号就自动建号。无 Bot 模式没有墙号可私聊，
如果没有别的自助通道，**同学根本注册不进来**。

而且管理员也**无法代为创建账号**——成员管理要求账号已存在（`POST /api/admin/members`
会返回「账号不存在，请先让该账号通过 Bot 注册或由运维创建」）。所以这个口子必须提前开。

### 唯一的通道：游客投稿

| 通道 | 位置 | 效果 |
| --- | --- | --- |
| **游客投稿** | 管理 · 插件配置 | 同学在登录页用「QQ 号 + 用户名 + 密码」自助注册 |

::: warning 聚合登录不能当进站通道
「聚合登录」的定位是**给已经存在的 Campux 账号额外绑定一种登录方式**，用之前该账号必须已经存在。
它不产生新的账号入口，所以**不算进站通道**。

账号始终以 Campux 账号为主体，聚合登录只是多一个登录选择。
:::

### 系统如何判定

判定逻辑（`readTenantIngressAvailability`）：

```text
available = 游客投稿已开启
```

切换运营模式时会检查这个值：

- `available = true` → 正常切换
- `available = false` → 返回 `409`，`code: NO_USER_INGRESS`，并说明缺什么

### 确实想先开墙再补配置

可以显式确认。两条路径都支持：

- **开墙向导**：点「无 Bot 模式运营」被拒后，会弹确认框；确认后带上 `confirmNoIngress: true` 重试
- **墙面设置**：保存被拒后弹确认框，确认后重试

确认后墙会正常开通，但**页面会持续提示**你没有进站通道（见下一节的红条），
直到你去开启插件为止。

## 三、开通方式

两种入口，效果完全相同。

### 方式一：开墙向导

流程：

```text
第 1 步  校园墙信息（名称、主题色、公告）
   ↓
第 2 步  接入墙号机器人
         └─ 底部有「不想接入机器人？用无 Bot 模式运营」按钮
   ↓
第 3 步  配置发布到 QQ 空间   ← 选择无 Bot 后这一步会被跳过
   ↓
第 4 步  开通完成
```

选择无 Bot 模式后：

- 步骤条自动变成 **3 步**（信息 → 机器人 → 完成）
- 「开通完成」的步骤号按可见步骤计算，不会显示成第 4 步
- 完成页会提示：**下一步要去开启游客投稿**，否则同学注册不进来

向导里的「无 Bot 模式运营」会立刻把 `readyAt` 写为当前时间——无 Bot 模式不需要墙号上线，
所以墙在切换的瞬间就算「已开通」，可以直接进入工作台。

### 方式二：切换已有校园墙

**管理 · 墙面设置 · 发布与通知 · 运营模式** → 选「无 Bot 模式运营」→ 保存。

保存时会：

1. 检查进站通道（不足则拦截，可选确认后继续）
2. 写入 `tenant_metadata.operate_mode = "manual"`
3. 写审计日志 `tenant.operate_mode.update`
4. 如果墙还没开通（`readyAt` 为空），同时写 `readyAt` 并记 `tenant.ready` 审计
5. 弹提示：**切换后未绑邮箱的用户下次登录会被询问是否绑定旧账号**

### 切换后立即发生什么

| 时机 | 行为 |
| --- | --- |
| 之后审核通过的稿件 | 停在 `approved`，进「待发布」队列 |
| 队列里已在途的自动发布 | **不会自动停止**（需手动或系统兜底，见下） |
| 已发布的内容 | 不受影响，仍在「已发布」列表 |

::: warning 切到 manual 后请立刻检查在途发布
如果有稿件正在自动发布队列里，它们会继续发出去，你再手动发一遍就重复了。
「稿件 · 待发布」顶部会显示「还有 N 条稿件在自动发布队列里」，
点「停止在途自动发布」把它们收回。

系统兜底：发布 worker 在真正对外发帖前会复查运营模式，已切到 manual 的会自动作废，
不会偷偷发出去。但这只是兜底，主动检查更可靠。
:::

## 四、注册渠道配置

**管理 · 墙面设置 · 注册与邮箱验证**

这一区决定「同学怎么注册进来」。

### 4.1 邮箱验证开关

| 状态 | 注册时需要填 |
| --- | --- |
| **关闭**（默认） | QQ 号 + 用户名 + 密码 |
| **开启** | 另外还要填邮箱 + 收验证码 |

开启邮箱验证的价值：确认同学真的拥有这个邮箱，日后可以通过邮箱找回密码。

::: info 影响范围
这个开关只影响**网页游客注册**。机器人建号、运营管理员开墙注册都不受影响。
:::

### 4.2 允许的邮箱后缀

开启邮箱验证后才出现。

- **不勾选任何后缀 = 不限制**，任意合法邮箱都能注册
- 勾选后只接受列表内的域名，其他一律拒绝

界面上有一条黄色说明专门强调「不勾选 = 不限制」，因为这个语义容易被误解成「全禁」。

**内置 15 个常用后缀**，点一下即选中：

```text
qq.com      foxmail.com   163.com     126.com     yeah.net
sina.com    sohu.com      139.com     aliyun.com  outlook.com
hotmail.com live.com      gmail.com   icloud.com  edu.cn
```

**自定义后缀**：输入框填 `edu.cn` 这类值，点「添加后缀」。
也可以随时点已选中的标签取消，或点「清空（改为不限制）」。

**上限 50 个**。预设按钮和自定义输入都受此限制，点满后会提示而不会超发请求。

**子域名自动匹配**：勾选 `edu.cn` 时，`student@mail.tsinghua.edu.cn` 也能通过。

**非法后缀会被拒绝**：提交 `com`（缺少二级域）这类值会返回
`400 INVALID_EMAIL_SUFFIX`，并指出具体是哪个条目 —— 不会静默变成「不限制」。
这个静默转换是个安全陷阱，所以特意做成报错。

### 4.3 QQ 邮箱与 QQ 号一致性

如果同学填的是 `<QQ号>@qq.com` 形式的邮箱，系统强制要求**登记的 QQ 号与邮箱前缀一致**。

```text
邮箱 123456@qq.com + QQ 号 123456  → 通过
邮箱 123456@qq.com + QQ 号 999999  → 拒绝：邮件前缀应为 123456
```

原因：否则有人可以用**别人的** QQ 邮箱注册成自己的号，之后归属再也说不清。

`foxmail.com` **不参与**这个校验 —— 它虽然同属腾讯，但前缀不保证是 QQ 号。

前端在填表时就会实时提示不一致，不用等到提交才知道。

## 五、发件服务配置

只有邮箱验证、密码找回、账号绑定才用到。在同一个「注册与邮箱验证」区域的下半部分。

### 5.1 两种发件模式

| 模式 | 说明 | 适用 |
| --- | --- | --- |
| **官方发件**（默认） | 用平台自带的 Resend，与运营管理员注册同一套 | 官方托管服务，无需配置 |
| **自定义 SMTP** | 自己填 SMTP 服务器、账号、授权码 | 自托管部署 |

如果本实例没有配 `RESEND_API_KEY`，选官方发件会提示「官方发件未启用」，此时必须改用 SMTP。

### 5.2 SMTP 字段

| 字段 | 说明 |
| --- | --- |
| SMTP 服务器 | 如 `smtp.qq.com` |
| 端口 | 465（SSL）/ 587 / 25 |
| SMTP 账号 | 通常是完整邮箱地址 |
| 密码 / 授权码 | **QQ/163 邮箱要用授权码，不是登录密码** |
| 发件人邮箱 | 通常与账号相同 |
| 发件人显示名 | 如「某某校园墙」 |

### 5.3 两条硬规则

这两条在服务端强制，界面同步给出反馈：

**规则一：开启邮箱验证前，发件配置必须完整**

否则返回 `400 MAIL_SENDER_INCOMPLETE`，并列出缺哪些字段。

**规则二：发件配置改动后，必须先发一封测试邮件成功，才能保存**

否则返回 `400 MAIL_SENDER_UNVERIFIED`。

操作顺序：

```text
1. 填好发件配置
2. 在「发送测试邮件到」填一个你能收到的邮箱
3. 点「发送测试邮件」
4. 去邮箱确认收到
5. 现在才能点「保存注册设置」
```

界面上有状态标记：

- 未验证 → 灰色「未验证」徽标，且（开启验证时）保存按钮禁用
- 已验证 → 绿色「已验证」徽标，提示「可以保存」

**任何字段再改动，验证状态立刻失效**，必须重测。这是刻意的：改了服务器还沿用旧的"已验证"
等于没验证。

::: tip 只是改后缀不用重测
仅调整「允许的邮箱后缀」这类**注册策略**、不动发件配置时，不需要重新测试。
:::

### 5.4 安全约束

系统对 SMTP 配置有几条硬性限制：

| 限制 | 原因 |
| --- | --- |
| 有认证时必须走 TLS（465 隐式，或服务器公告 STARTTLS） | 否则授权码明文过网 |
| 不允许指向 `127.0.0.0/8`、`localhost`、`::1` | 回环地址在正常部署里没有理由当邮件服务器 |
| 不允许指向 `169.254.0.0/16`、`fe80::/10` | 链路本地地址，是云元数据服务的典型入口 |
| **允许**私网（`10/8`、`172.16/12`、`192.168/16`） | 自托管场景运营者本就需要连自己的内网中继 |

如果你的内部中继不支持 STARTTLS，请改用 465（隐式 TLS）或免认证中继。

## 六、用户进站流程

### 6.1 场景 A：游客投稿（未开邮箱验证）

```text
同学打开登录页
   ↓
看到「还没有账号？」→ 点「注册」
   ↓
填：QQ 号、用户名、密码
   ↓
点「注册并登录」
   ↓
直接进入墙内，成为 submitter
```

### 6.2 场景 B：游客投稿（已开邮箱验证）

```text
填：QQ 号、用户名、密码
   ↓
填：邮箱（界面会提示本墙接受哪些后缀）
   ↓
点「获取验证码」→ 邮箱收到 6 位码
   ↓
填验证码 → 点「注册并登录」
```

失败情况：

| 情况 | 结果 |
| --- | --- |
| 邮箱后缀不在白名单 | `400`，提示接受哪些后缀 |
| QQ 邮箱前缀与 QQ 号不符 | `400`，指出应为哪个 QQ 号 |
| 验证码错误 | `400`，剩余尝试次数递减（最多 5 次） |
| 验证码过期 | `400`，需重新获取（10 分钟有效） |
| QQ 号已被注册 | `409` |
| 邮箱已被注册 | `409` |
| 发码太频繁 | `429`，60 秒冷却 + 每小时 5 次 |
| 发信服务发送失败 | `502`，**并作废该验证码** |

::: warning 验证码不会泄露
只有在本实例**完全没有邮件服务**（既没配 Resend 也没配 SMTP）时，接口才会直接回显验证码
——这是为了让自托管无邮件环境仍能注册。

一旦配了发件服务但发送失败，接口返回 `502`，**不会**把验证码交给调用者，
刚生成的验证码也会被删除。
:::

### 6.3 场景 C：聚合登录（登录方式，不是注册入口）

聚合登录是**给已经存在的账号绑定一种额外登录方式**，不产生新账号。

```text
先有 Campux 账号（通过游客投稿或 Bot 注册）
   ↓
到「服务 · 账户设置」绑定聚合登录
   ↓
之后可以直接扫码登录这个账号
```

**它不能用来注册**。所以无 Bot 模式下把它当作注册通道是错的——墙仍然需要开启「游客投稿」，
否则新同学进不来。

绑定聚合登录的账号，其主体始终是 Campux 账号：稿件、身份、角色都挂在 Campux 账号上。

### 6.4 登录方式

注册后两种凭据等价：

- **QQ 号 + 密码**
- **邮箱 + 密码**

已绑定聚合登录的账号还可以扫码登录。

## 七、投稿流程

无 Bot 模式下投稿渠道只有**网页**（没有私聊墙号这条路）。

### 7.1 投稿页

移动端布局从上到下：

```text
Campux 标题 + 当前墙名
黄色公告条（管理员配置）
头像 + 大文本框
图片缩略图 + 添加图片（约 70px 方块）
匿名投稿开关（绿色块）
投稿规则（橙色块）
彩色渐变提交按钮
底部导航
```

### 7.2 可配置项

| 功能 | 说明 | 配置位置 |
| --- | --- | --- |
| 标题 | 稿件可选标题 | — |
| 正文 | 最多 1000 字 | — |
| 图片 | 最多 9 张，单张默认上限见墙面设置 | 墙面设置 · 图片压缩 |
| 匿名 | 默认匿名，可切实名 | — |
| 匿名头像 | 插件开启时可选 | 插件配置 · 匿名头像 |
| 背景色 / 文字色 | 插件开启时可选 | 插件配置 · 多彩投稿 |
| 字体 | 插件开启时可选 | 插件配置 · 字体选择 |
| 话题标签 | 插件开启时可选，最多 5 个 | 插件配置 · 热度榜 |
| 草稿 | 本地自动保存，刷新不丢 | — |
| 待审配额 | 每人最多同时保留 N 条待审 | 墙面设置 · 每人待审上限 |

### 7.3 提交后

```text
status = pending_approval
```

出现在管理员/审核员的「审核稿件」列表里。

## 八、审核流程

### 8.1 审核页面

**稿件 · 审核稿件**，可按状态筛选：

`待审核 / 已通过 / 已拒绝 / 发布中 / 已发布 / 待撤回 / 已忽略撤回 / 已撤回 / 发布失败 / 全部`

卡片显示：稿件编号、作者昵称 + QQ、匿名状态、图片数、创建时间、正文、图片、标签。

### 8.2 通过稿件

点「通过」，稿件发生：

```text
pending_approval → approved
```

**无 Bot 模式下的关键点**：`approved` 就是终点。不会再有任何自动流程接手它，
它会立刻出现在「稿件 · 待发布」队列里。

界面提示会说「已通过，稿件已进入「待发布」，请到待发布页手动发到 QQ 空间」，
而不会说「正在生成发布任务」。

### 8.3 一键通过

「待审核」筛选下有一条绿色条：**一键通过全部**。

点击前会弹确认框，要求你确认已逐个审核过。确认后：

- 所有待审稿件变成 `approved`
- 无 Bot 模式下它们全部进「待发布」
- 同样不会触发任何自动发布

### 8.4 拒绝稿件

点「拒绝」，可以填理由：

- 填了理由 → 用你填的
- 不填（点「不填写理由」）→ 用默认理由「无理由」

拒绝后 `status = rejected`，并写一条 `postLog`。

**拒绝理由如何传到用户**：

| 模式 | 传递方式 |
| --- | --- |
| 机器人模式 | 尝试通过墙号私聊通知作者 |
| **无 Bot 模式** | **没有私聊通道**，理由直接显示在用户自己的稿件列表里 |

用户在自己「你的稿件」里看到红色块：

```text
┌─ 审核未通过 ────────────┐
│ 信息不完整，请补充…      │
└────────────────────────┘
```

所以**填一个有用的理由**在无 Bot 模式下格外重要 —— 这是用户唯一能看到解释的地方。

### 8.5 AI 审核辅助

如果开了 AI 审核插件，审核卡片会显示：

- 风险等级、分类、敏感发现
- AI 建议动作（approve / reject / manual_review）
- 参考拒绝理由（可一键复制）
- 自动决策倒计时（auto 模式下）

无 Bot 模式与 AI 审核**不冲突**：AI 通过后稿件同样停在 `approved` 等你手动发。

### 8.6 审核权限

| 角色 | 能做什么 |
| --- | --- |
| `submitter` | 只能看自己的稿件 |
| `reviewer` | 审核通过/拒绝，看统计 |
| `admin` | 审核 + 管理 + 待发布队列操作 |

::: info 待发布队列只对 admin 开放
`/api/admin/pending-publish/*` 全部要求 `admin` 角色。审核员可以审核，但不能发布。
:::

## 九、待发布队列

这是无 Bot 模式的**主工作台**。

### 9.1 入口

**稿件 · 待发布**（仅管理员可见）。

页签上带角标显示积压数量，角标在进入页签前就已预取，不需要先点开才有数字。

### 9.2 什么稿件会进队列

判定条件（三者同时满足）：

```text
status = approved
AND 没有任何「在途或成功」的发布尝试
    （queued / running / waiting_cookies / succeeded 都不算）
AND 不属于任何批量发布批次
```

::: info 为什么不是「没有任何尝试」
从机器人模式切过来时，被停下的稿件会留下 `skipped` 尝试，失败会留下 `failed`。
这些稿件已经不在自动队列里了，必须能进待发布 —— 否则既发不出去也删不掉。
:::

### 9.3 顶部提示区

队列顶部可能出现的提示，按需显示：

**① 进站通道缺失（蓝色）**

```text
这个墙还没有开放任何进站通道，普通同学注册不进来。
→ 去「管理 · 插件配置」开启「游客投稿」…
```

出现条件：当前是 manual 模式，且 `ingress.available = false`。

**② 在途发布未停止（红色）**

```text
还有 N 条稿件在自动发布队列里。无 Bot 模式下它们不应该继续自动发出…
[ 停止在途自动发布 ]
```

出现条件：`inFlight > 0`（`publishing` 或 `partially_failed` 状态的稿件数）。

**③ 滞留稿件（琥珀色，仅机器人模式）**

```text
切回机器人发布后，有 N 条审核通过的稿件仍滞留在这里，不会自动发布。
[ 一键补入自动发布队列 ]
```

出现条件：当前是 bot 模式且 `residual > 0`。

### 9.4 筛选与排序

| 控件 | 选项 | 说明 |
| --- | --- | --- |
| 搜索框 | 关键词 | 匹配正文、稿件编号、作者 QQ、作者昵称；回车或点「搜索」触发 |
| 匿名筛选 | 全部 / 只看匿名 / 只看实名 | 即时生效 |
| 配图筛选 | 不限 / 只看有配图 / 只看纯文字 | 即时生效 |
| 排序 | 最早投稿优先（默认）/ 最新优先 / 优先多图 | 即时生效 |
| 每页条数 | 10 / 20 / 30 / 50 | 即时生效 |

::: tip 配图筛选已修正分页
配图筛选会先过滤完整数据集再分页，`total` 也按过滤后的数量计算。
不会出现「第一页空、目标稿件在第 N 页」的情况。
:::

### 9.5 每张稿件卡片

```text
[ ] #12 · 昵称 · QQ 123456          2026-11-20 14:30
正文（最多显示 4 行，超出省略）
┌──────────────────────────┐
│      渲染图预览           │  ← 点击查看大图
└──────────────────────────┘
[缩略图][缩略图]                        ← 原始配图，点击查看/另存
附件 2 个（点上方缩略图可查看原图并另存）
        [查看渲染图] [保存图片] [复制文案] [确认已发布]
```

各元素的作用：

| 元素 | 作用 |
| --- | --- |
| 复选框 | 多选，用于批量确认 |
| 渲染图 | 稿件卡片图，就是你要发到空间的那张 |
| 配图缩略图 | **原始附件**，手动发说说时要连这些一起发 |
| 查看渲染图 | 新窗口打开大图 |
| 保存图片 | 下载为 `campux-post-<编号>.jpg` |
| 复制文案 | 按墙面设置的模板生成说说文案并复制 |
| 确认已发布 | 单条确认，状态推进到 `published` |

::: tip 配图缩略图是这次补上的
之前只显示「附件 N 个」的文字，运营者看不到也下载不了原图。
手动发说说时必须连配图一起发，所以现在直接给出可点开的缩略图。
:::

### 9.6 说说链接（可选）

卡片上方有一个输入框：

```text
说说链接（可不填）：填了会记在这批稿件上，之后可在「已发布」里点开对照；
留空直接确认也不影响状态推进。
```

**完全可选**。不填也能正常确认发布。

| 输入 | 结果 |
| --- | --- |
| 不填 / 只填空格 | 正常确认，`manualPublishUrl = null` |
| `https://user.qzone.qq.com/…` | 正常确认，并把链接记在稿件上 |
| `user.qzone.qq.com/…`（缺协议） | 确认成功，但**链接被忽略**，并明确提示「格式不合法，未记录」 |

填了链接的好处：之后在「已发布」列表里能直接点开对照，事后追溯「到底发到哪条说说」。

### 9.7 批量操作

勾选多条后，工具栏出现：

| 按钮 | 行为 |
| --- | --- |
| 全选本页 | 选中/取消当前页全部 |
| 确认选中 | 只确认勾选的稿件 |
| 一键确认全部已发布（N） | 确认**当前筛选条件下**的全部稿件 |

::: danger 「一键确认全部」有二次确认
点击后会弹框：

> 当前待发布共 N 条稿件，确认后它们会立刻变成「已发布」…
> 这里只是确认状态，系统不会再自动发一次。

因为这是个不可逆的批量操作（虽然可以退回），所以强制确认。
:::

**确认全部会遵循当前筛选**：如果你筛了「只看匿名」，就只确认匿名的那批，
不会动屏幕外的稿件。这条前后端都做了，避免了「界面上筛了、后台却按全量确认」。

### 9.8 失败明细

批量确认部分失败时，红色面板列出：

```text
有 2 条稿件未能确认发布
#15 · 状态已变化，不再是可以确认的待发布稿
#16 · 稿件已不在待发布状态（可能已被发布或进入自动队列）
```

失败不影响成功的那批 —— 每条稿件独立事务处理。

### 9.9 停止在途自动发布

从机器人模式切过来时用。

**按钮出现条件**：`inFlight > 0`。

点击后：

| 尝试状态 | 处理 |
| --- | --- |
| `queued` / `waiting_cookies` / `failed` | 标为 `skipped`，稿件退回 `approved` |
| `running` | **跳过**（正在发送中，停不下来），等它结束 |
| `succeeded` | 跳过（已经发出去了） |

除单条处理外，还会检查兄弟目标：如果这条稿件的其他发布目标已经成功或在跑，
就不把它退回待发布（否则会同时从「已发布」和「待发布」里消失）。

批量稿件会退出批次收集，回归单稿待发布。

## 十、手动发布与确认

这是无 Bot 模式的核心动作。

### 10.1 完整动作序列

```text
① 在待发布队列找到稿件
② 点「查看渲染图」确认效果，必要时「保存图片」下载
③ 点配图缩略图，把原图也另存下来
④ 点「复制文案」，得到带 #编号 的说说文案
⑤ 打开 QQ 空间（手机或电脑），用墙号手动发说说：
      - 上传渲染图
      - 上传原图
      - 粘贴文案
⑥ 复制这条说说的链接（可选但推荐）
⑦ 回到待发布队列，粘贴链接 → 点「确认已发布」
```

### 10.2 确认后发生什么

```text
status: approved → published
manualPublishedAt: 写入当前时间
manualPublishUrl: 写入你填的链接（没填则 null）
publishSummary: "管理员手动发布"
postLog: 新增一条「管理员确认已手动发布」
auditLog: post.manual_publish
```

稿件立刻从待发布队列消失，出现在「稿件 · 已发布」列表里。

### 10.3 说说文案模板

**管理 · 墙面设置 · 发布与通知 · 无 Bot 模式补充设置**

| 设置 | 作用 |
| --- | --- |
| 墙号 QQ（渲染图角落） | 渲染图右下角显示的头像；留空用默认头像 |
| 说说文案前缀 | 每条文案最前面固定加一句 |
| 说说文案后缀 | 每条文案最后面固定加一句 |
| 带「#稿件编号」 | 默认开启 |
| 实名稿件带「@作者QQ」 | 默认关闭；**匿名稿件永远不带** |

生成规则（`renderManualPublishCaption`）：

```text
第一行： [前缀] [#编号] [@作者QQ]
第二行： [后缀]
```

例：

```text
前缀 "#校园墙投稿"、带编号、带 @作者QQ、后缀 "欢迎私信投稿"
→
#校园墙投稿 #12 @123456
欢迎私信投稿
```

所有部分都关掉时，兜底输出 `#12`（至少保留编号）。

### 10.4 确认错了怎么办

**单条回退**：

在「稿件 · 已发布」找到这条稿件（手动发布过的会有「退回待发布」按钮），点一下：

```text
published → approved
manualPublishedAt / manualPublishUrl / publishSummary 清空
postLog: 新增「管理员撤销「确认已发布」，稿件退回待发布」
auditLog: post.manual_publish.revert
```

稿件回到待发布队列，可以重发。

**回退的限制**：

| 条件 | 是否可回退 |
| --- | --- |
| 管理员手动确认的稿件 | 可以 |
| 有成功或在跑的自动发布尝试 | 不可以（那是真的发出去了） |
| 自动发布链路产生的 `published` | 不可以（没有 `manualPublishedAt`） |
| 只有 `skipped` / `failed` 终态尝试 | **可以**（这些并没有真正发出去） |

状态变更、日志、审计在**同一个事务**里，任何一步失败都回滚，稿件仍可重试。

**批量误确认**：目前需要逐条在「已发布」里退回。确认前请看清二次确认框里的条数。

### 10.5 已发布列表里的手动发布标识

手动发布过的稿件在「已发布」卡片上会显示：

```text
┌─ 手动发布记录 ────────────────────────────┐
│ 🔗 打开这条说说        [已在空间手动删除] │
└──────────────────────────────────────────┘
```

没填链接时显示：

```text
┌───────────────────────────────────────────┐
│ 这条稿件是手动发到 QQ 空间的，系统没有发帖  │
│ 记录、无法自动删除。请到空间删除说说后点右侧 │
│ 确认。              [已在空间手动删除]     │
└───────────────────────────────────────────┘
```

## 十一、撤回流程

无 Bot 模式的撤回是**最容易误解**的一环。

### 11.1 为什么不能一键撤回

机器人模式下，撤回 = 调用 QZone 接口把说说设为「仅自己可见」。
这需要系统里存着**发帖记录（tid）**。

无 Bot 模式的稿件是你手动发出去的，**系统里没有任何发帖记录**。
所以程序删不了那条说说。

### 11.2 旧行为（已修复）

之前的实现是：发现没有发帖记录，就直接把稿件标成 `recalled`，日志写
「没有可撤回的 QZone 发表记录，直接标记为已撤回」。

结果：**界面上显示已撤回，空间里的说说其实还在。** 这是个会误导人的假成功。

### 11.3 现在的行为

撤回接口会返回 `409`，`code: RECALL_MANUAL_REQUIRED`，并说明：

> 这条稿件没有可撤回的发布记录：内容是管理员手动发到 QQ 空间的，系统无法自动删除

界面会弹提示引导你走手动流程。

### 11.4 正确流程

#### 情况 A：作者自己申请撤回

```text
① 作者在自己的稿件里点「申请撤回」，填理由
      → status: published → pending_recall
② 运营者在「审核稿件」顶部「待处理撤回请求」看到它
③ 到 QQ 空间手动删除那条说说
④ 回到卡片，点「已在空间手动删除」
      → status: pending_recall → recalled
```

审核卡片上现在有「已在空间手动删除」按钮，**直接在这个状态就能完成**，
不需要去「已发布」列表找 —— 因为 `pending_recall` 的稿件根本不在已发布列表里。

其他可选操作：

| 按钮 | 效果 |
| --- | --- |
| 拒绝撤回 | 稿件恢复 `published`，理由发给作者 |
| 忽略 | 标记 `recallIgnored`，从顶部队列折叠，之后仍可处理 |
| 同意撤回 | 机器人模式下有效；**无 Bot 模式会因无记录而失败** |

#### 情况 B：管理员直接撤回

「已发布」列表里，管理员可以对已发布稿件点「撤回」/「静默撤回」。

无 Bot 模式下同样会因无发帖记录失败，界面提示改走「已在空间手动删除」。

### 11.5 撤回后的状态

```text
status = recalled
recallIgnored = false
postLog: 「管理员已到 QQ 空间手动删除说说并确认撤回」
auditLog: post.recall.manual_complete
```

用户在自己的稿件里看到「已撤回」。

## 十二、模式互切

### 12.1 bot → manual（切到无 Bot）

**切换时系统做的**：

1. 校验进站通道（不足则拒绝或要求确认）
2. 写 `operate_mode = manual`
3. 记 `tenant.operate_mode.update` 审计
4. 弹提示告知「未绑邮箱用户下次登录会被询问绑定旧账号」

**你必须做的**：

```text
① 打开「稿件 · 待发布」
② 看顶部是否有「还有 N 条稿件在自动发布队列里」
③ 有就点「停止在途自动发布」
④ 检查有没有已经发出去、但你以为没发的稿件
```

**为什么必须做**：不停止的话，队列里的稿件会继续自动发出去，
你再手动发一遍 → 空间出现两条一样的说说。

**系统兜底**：发布 worker 在真正调 QZone 接口前会复查运营模式，
已切到 manual 的会作废该次发布。但这依赖时序，主动停止更可靠。

### 12.2 manual → bot（切回机器人）

**切换后**：

- 之后审核通过的稿件会正常进自动发布队列
- **之前积压在待发布的稿件不会自动进队**（它们没经过审核入队流程）

**你必须做的**：

```text
① 打开「稿件 · 待发布」
② 看到琥珀色提示「有 N 条审核通过的稿件仍滞留在这里」
③ 点「一键补入自动发布队列」
```

补入时会按当前发布模式决定：

- **逐条发布** → 每条稿件单独入队
- **批量发布** → 加入批次收集

单条失败只记录日志，不阻断其余稿件。

### 12.3 反复切换

反复切换本身没问题，但要注意：

- 每次切换都会触发「未绑邮箱用户下次登录询问绑定账号」（见下一节）
- 每次 bot → manual 都要重新检查在途发布
- 每次 manual → bot 都要重新补投滞留稿件

## 十三、账号合并

### 13.1 为什么会有这个问题

考虑这个真实场景：

```text
阶段一（无 Bot 模式）：
  同学用「游客投稿」注册了账号 A（QQ 号 111111，绑邮箱 a@qq.com）
  发了几条稿件

阶段二（切到机器人模式）：
  同学私聊墙号投稿 → 系统按 QQ 号 222222 自动建了账号 B
  （因为他的墙号 QQ 是 222222，和注册时用的 111111 不是同一个）

结果：同学登录账号 B，看不到阶段一的稿件。
```

### 13.2 系统怎么提示

管理员切换运营模式后，**未绑邮箱**的账号下次登录时，会弹「绑定之前的账号」对话框。

提示条件（`shouldPromptAccountMerge`）：

```text
email IS NULL  AND  mergedAt IS NULL
```

也就是说：

| 情况 | 是否提示 |
| --- | --- |
| 没绑邮箱、没合并过 | ✅ 提示 |
| 已绑邮箱 | ❌ 不提示（说明已走过注册流程） |
| 已合并过 | ❌ 不提示 |

### 13.3 合并流程

```text
① 弹窗出现：「绑定之前的账号？」
② 输入「之前账号的 QQ 号」→ 点「查询」
③ 系统显示预览：旧账号 QQ、昵称、可迁移稿件数
④ 验证码发到**旧账号绑定的邮箱**
⑤ 填验证码 → 点「确认绑定」
```

**旧账号没有绑定邮箱时**：无法证明归属，直接返回
`400 MERGE_PROOF_UNAVAILABLE`，要求联系管理员。

::: danger 凭证必须是旧账号的邮箱
这是安全关键点。用「当前账号的邮箱」或「用户随便填的邮箱」作为凭证，
等于只要登录了自己的账号、知道别人 QQ 号，就能吞并别人的账号。

所以：验证码**只发到旧账号绑定的邮箱**，不接受 `body.email` 覆盖，
`mergeUserAccounts` 内部也强制这个条件。
:::

**QQ 号不一致时**（常见情况）：弹窗会明确提示

> 旧账号的 QQ（222222）与当前登录账号（111111）不一致。
> 确认绑定后，旧账号的稿件会并入当前账号，当前账号的 QQ 仍是 111111，旧账号停用。

注意措辞：**保留的是当前账号**，旧账号停用。

### 13.4 合并的具体动作

在一个事务里完成：

| 对象 | 处理 |
| --- | --- |
| 稿件 | 当前墙内的稿件，作者改为新账号 |
| 成员身份 | 若新账号已有该墙身份 → 删旧那条；否则迁过来 |
| 关注 | 迁移，冲突的（同 postId）删旧留新 |
| 意见反馈 / 毕业去向 / 广播 / 竞选 | 当前墙内的迁移 |
| 竞选投票 | 迁移，同 campaignId 冲突的删旧 |
| 第三方身份 | 按 `(provider, providerUserId)` 判重，冲突删旧、其余迁移 |
| 登录会话 | 旧号会话全部删除 |
| 旧账号 | `mergedAt` 打标记，`mergedIntoUserId` 指向新账号 |
| 审计 | 写 `UserMerge` 记录 + `user.merge` 审计 |
| 登录态 | 旧号密码**不变**，但旧号已停用 |

**并发保护**：旧账号的"接管"用条件更新（`mergedAt: null`），
两个请求同时合并时只有一个能成功，另一个报「已被合并」。

**跨墙限制**：旧账号如果还属于**其他校园墙**，拒绝自助合并
（因为合并只迁当前墙的数据，却会做全局重定向，其他墙会解析到没有该墙身份的主账号）。
这种情况需要系统运维处理。

### 13.5 跳过与补做

弹窗可以点「以后再说」跳过。之后随时可以在
**服务 · 账户设置 · 绑定之前的账号** 里补做。

### 13.6 合并后的登录行为

合并**不影响登录方式**。旧账号的 QQ 号、邮箱、密码都仍然可用：

| 登录方式 | 结果 |
| --- | --- |
| 旧 QQ 号 + 密码 | 登录到主账号 |
| 旧邮箱 + 密码 | 登录到主账号 |
| 主账号 QQ 号 + 密码 | 登录到主账号 |
| 主账号邮箱 + 密码 | 登录到主账号 |

用旧凭据登录时，界面提示「该账号已合并，已为你登录到合并后的账号」。

**忘记密码**同样作用于主账号 —— 用旧邮箱收到的验证码，重置的是主账号密码。
不会出现「改了密码却登不进」的情况。

## 十六、常见问题

**Q：切到无 Bot 模式后，之前审核通过的稿件去哪了？**

它们还在 `approved` 状态，会出现在「稿件 · 待发布」里。
但如果在切换前已经进了自动发布队列，需要先点「停止在途自动发布」。

**Q：为什么我的「停止在途自动发布」按钮不出现？**

这个按钮只在 `inFlight > 0` 时显示。如果显示不出来，说明当前没有
`publishing` / `partially_failed` 状态的稿件，队列是干净的。

**Q：确认发布后还能改吗？**

可以。在「稿件 · 已发布」里点「退回待发布」，稿件会回到队列，可以重新发。
但只有**管理员手动确认**的稿件能退回，自动发布的不行。

**Q：说说链接一定要填吗？**

不用。留空完全不影响确认。填了的好处是之后能在「已发布」里点开对照，
事后追溯「到底发到哪条说说」。

**Q：为什么我填了链接但没记上？**

链接必须以 `http://` 或 `https://` 开头。填了 `user.qzone.qq.com/...` 这种缺协议的，
系统会确认发布但忽略链接，并提示「格式不合法，未记录」。

**Q：同意撤回为什么失败了？**

无 Bot 模式的稿件没有发帖记录，程序删不了说说。正确做法：
到 QQ 空间手动删除 → 回到「待处理撤回请求」卡片点「已在空间手动删除」。

**Q：「一键确认全部」会不会把屏幕外的稿件也改掉？**

不会。它遵循当前筛选条件。如果你筛了「只看匿名」，就只确认匿名的那批。

**Q：开启邮箱验证后，原有的用户还能登录吗？**

能。邮箱验证只影响**新的网页注册**，已有账号和登录不受影响。

**Q：只绑了聚合登录、没有真实 QQ 号的同学怎么找回密码？**

账号主体始终是 Campux 账号。这类账号如果没有可用于私聊的 QQ 号，机器人模式下
`#重置密码` 走不通；若也没绑邮箱，网页找回会返回 `409 RESET_UNAVAILABLE`，需要联系管理员。

所以**建议在绑定聚合登录的同时绑定邮箱**——邮箱是这类账号唯一可靠的自助找回手段。

**Q：聚合登录能用来注册新账号吗？**

不能。聚合登录的定位是给**已经存在**的 Campux 账号绑定一种额外登录方式，
它不产生新的账号入口。无 Bot 模式下的注册通道只有「游客投稿」。

**Q：邮箱验证的「不限制后缀」是怎么表示的？**

**不勾选任何后缀**就是「不限制」。界面上有专门的黄色说明强调这一点，
所以不要以为留空是「全禁」。如果你看到保存后是空列表，那就是不限制。

**Q：发件配置改了但没重新测试，为什么保存不了？**

这是刻意的：改了配置还沿用旧的「已验证」状态，等于没验证。
任何字段再改动，都必须重新发一封测试邮件确认收到。

**Q：无 Bot 模式下，用户被封禁了还能投稿吗？**

不能。封禁的检查与运营模式无关，被封禁账号进入该墙只会看到封禁信息。
